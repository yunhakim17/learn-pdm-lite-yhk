# Block 2: 공개

> 📖 공식 문서: https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site
> ```

## EXPLAIN

### 1. 정의

| 용어 | 뜻 |
|---|---|
| GitHub 저장소 | 파일과 변경 기록을 담는 온라인 폴더. public이면 누구나 볼 수 있다. |
| GitHub Pages | 저장소의 `index.html`을 웹 주소(`https://아이디.github.io/저장소이름/`)로 보여 주는 기능. |

### 2. 왜 공개하는가 — 파일로 보낼 때와 비교

| 기준 | 파일을 메일·메신저로 보낸다 | Pages 주소를 보낸다 |
|---|---|---|
| 받는 사람 | 내려받아 열어야 한다 | 주소만 누르면 휴대폰에서도 열린다 |
| 고쳤을 때 | 파일을 다시 보낸다 | 같은 주소가 새 결과로 바뀐다 |
| 위험 | 사내 자료가 섞여 나갈 수 있다 | 공개 전에 무엇이 올라가는지 확인해야 한다 |

### 3. 공개 전 보안 수칙

- 비밀번호·토큰은 Claude에게 입력하지 않는다. GitHub 로그인은 브라우저에서 수강생이 직접 승인한다.
- 회사 실제 센서 데이터는 공개 저장소에 올리지 않는다. 오늘 데이터는 **실습용 가상 데이터**다.
- 공개는 되돌리기 어렵다. 올라갈 파일 목록을 보고 나서 공개한다.

## EXECUTE

아래 프롬프트를 붙여 넣으라고 안내한다.

```
pdm-lite-lab 의 진동 그래프를 GitHub Pages로 공개해 줘.
1. GitHub 로그인 상태를 확인한다. 안 되어 있으면 브라우저 로그인용 일회용 코드만 알려 준다.
   비밀번호나 토큰을 나에게 묻지 않는다.
2. 올릴 파일 목록(index.html, anomalies.csv, Day5_sensor_50_virtual.csv)을 먼저 보여 주고 내 확인을 받는다.
3. 확인하면 public 저장소 pdm-lite-lab 을 만들어 올리고 GitHub Pages를 켠다.
4. Pages 주소가 열리는지 확인해 알려 준다.
5. 동료에게 보낼 공유 메시지를 세 줄로 써 준다 (무엇을 봤는지 · 설비B가 정비 신호인 이유 · 주소).
```

사람이 직접 하는 일:
1. 일회용 코드가 나오면 브라우저에서 `https://github.com/login/device`를 열고 코드를 넣는다.
2. 다음 화면 맨 아래 **Authorize** 버튼을 누른다.
3. 올릴 파일 목록을 보고 Claude에게 "확인"이라고 답한다.

### 확인할 것 (Phase B)

- `gh repo view pdm-lite-lab`으로 저장소가 public으로 있는가
- Pages 주소(`https://<아이디>.github.io/pdm-lite-lab/`)가 열리고 진동 그래프와 "실습용 가상 데이터" 문구가 보이는가
- 공유 메시지에 Pages 주소가 들어 있는가

막히면 원인을 Claude Code에게 찾게 하는 후속 프롬프트를 준다. 정답은 "정답 보기" 요청이 있을 때만 연다.

```
Pages 주소가 열리지 않는다. 저장소 설정의 Pages 배포 상태를 확인하고 원인을 알려 줘. 몇 분 걸리는 경우면 그렇다고 말해 줘.
```
